# K8s Configuration

All defined configurations of k8s cluster are managed by the `control plane -> CP`, specifiically the `apiserver` on it. Interaction  (requests to) with the `CP` could be from the: `CLI (kubectl)`, `UI` or `API`. The configuration of kube processes is defined is `json/yaml` format.

## Parts of a k8s configuration file
- version and type declaration: `apiVersion`, `kind`

    - kind speccifies what part of the architecture is being configured: `deployment for pod` or `service for networking`


- metadata: `metadata`
    - holds the name of the deployment and descriptions


- specification: `spec`
    - stores the attributes of the component such as `replica for pods (deployemnt)` or `ports for service`

- status:
    - A phenomenon to reconcile reality with the desired state. Typically generated by k8s itself.

## Cluster setup

- Minikube
    -
    - This is the production equivalent of testing k8s jobs locally.
    - Comprises of one node for managing worker and master processes.


- Kubectl (CLI Interaction)
    -
    This is the most essential tool/component among the different clients (API, UI) that interact with `apiserver of the master processes`.

- Minikube Installation
    -
    - To run minikube locally, there must be a virtual-machine or container manager like docker or similar as a driver.
    - [install minikube](https://minikube.sigs.k8s.io/docs/start/?arch=%2Flinux%2Fx86-64%2Fstable%2Fbinary+download)

- Interact with minikube
    - 
    - `minkube start` : to start cluster. This should automatically pick up the docker driver if installed but if cluster fails to start with docker installed, then ; `minikube start --driver docker` 
    - `minikube status` : to verify minikube cluster state
